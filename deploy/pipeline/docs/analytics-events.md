# 区域与越线事件

## 数据流

```text
RGA2 BGR -> RKNN检测框 -> 归一化中心点 -> 轻量轨迹
                                      -> 区域进入/离开
                                      -> 有方向越线
                                      -> 非阻塞事件队列
                                      -> events/events.jsonl
                                      -> Web /api/events
```

规则坐标和检测框都对应旋转后的输出画面，因此事件判断不再做第二次旋转或主/子流
缩放。Web把UTF-8规则名称编码成十六进制规则文件；C++只解析固定字段，避免在媒体
进程中引入通用JSON解析器。

## 事件字段

每行是独立JSON对象：

```json
{"time":"2026-11-02T10:00:00.123Z","type":"line_cross","rule":"门口",
 "direction":"side_b_to_a","label":"人","class_id":11,"score":0.9132,
 "track_id":7,"pts_us":123456789,"center":[0.531250,0.472222]}
```

事件类型：

- `region_enter`：新轨迹首次出现在区域内，或已有轨迹从外部进入。
- `region_exit`：已有轨迹中心从区域内移动到外部。
- `line_cross`：轨迹中心离开线附近死区后从一侧移动到另一侧。

方向由绘线起点到终点定义为 `side_a_to_b` / `side_b_to_a`。部署时应在规则名称中
注明业务方向，例如“入口线（左到右为进入）”，并用真人走动确认一次方向。

## 跟踪和去抖边界

- 只在相同类别内按中心距离和框尺寸做最近邻匹配，单次AI采样最多允许移动画面宽度
  的20%。默认容忍连续3个AI结果未匹配，默认同一轨迹/规则/事件2秒内去重。
- 该算法CPU开销低，适合单摄像头低密度目标；它不是外观ReID。相同类别目标交叉、
  严重遮挡或运动过快时可能换ID或漏过线。
- 新轨迹首次出现在区域内会产生 `region_enter`；目标消失不会伪造 `region_exit`。
- 事件文件达到8 MiB后轮转为 `.1`。事件使用容量256的最新队列，磁盘慢时AI线程
  不阻塞；丢弃数和写错误分别体现在 `dropped` 与 `write_error` 指标。

## Web操作

1. 打开“区域与越线”，选择工具并绘制规则。
2. 规则名称应表达位置和方向，保存规则。
3. 在“码流与AI”保存配置时勾选“保存后立即重启并应用”，或点击顶部重启管线。
4. 让目标连续经过规则；打开“事件与文件”刷新事件。
5. `/api/metrics`中确认 `event_generated == event_written`、
   `event_dropped == 0`、`event_write_errors == 0`。

配置文件为持久化的 `analytics.rules`，事件文件为持久化的
`events/events.jsonl`；A/B升级和自动回滚不会删除它们。
