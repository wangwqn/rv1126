# 光学端到端时延测试

## 测量边界

光学对拍从“真实计时器像素出现在摄像头前”开始，到“同一帧在客户端显示器上
出现”结束，覆盖摄像头曝光、VI/ISP、RGA/OSD、VENC、RTSP/RTP、Wi-Fi、客户端
接收缓存、H.264解码和显示刷新。它不依赖开发板与宿主机时钟同步。

建议目标如下。这些是预算，不是把板端内部计数器简单相加得到的实测值：

| 阶段 | 建议目标 |
|---|---:|
| VI/ISP | 20–40 ms |
| RGA/OSD | 2–8 ms |
| VENC | 10–35 ms |
| RTP发送 | 2–20 ms |
| Wi-Fi | 2–30 ms |
| 客户端缓存、解码和显示 | 50–100 ms |
| 光学端到端 | 120–250 ms |

板端 `--latency-csv` 用于定位内部阶段，光学结果用于最终端到端验收。二者的测量
边界不同，不能用 `server_total` 冒充端到端结果。

## 同屏布置

1. Windows宿主机连接开发板热点并确认RTSP主流可播放。
2. 用Chrome/Edge打开 `scripts/optical_latency_timer.html`，按F11全屏或保持计时器
   完整可见。页面使用九位机器码 `HHMMSSmmm`，下方普通数字只供人工核对。
3. 将IMX415正对计时器，尽量垂直屏幕，避免摩尔纹、反光、自动曝光过暗和严重透视。
4. 在同一台宿主机上打开RTSP主流，把播放器窗口放到计时器旁边。摄像头视野只需
   包含计时器，不要包含播放器窗口，以免产生递归画面。
5. 宿主机桌面此时应同时出现“浏览器中的实时计时器”和“播放器视频中的旧计时器”。
   对桌面截图即可在同一时刻保存两者，不需要第二台相机。

播放器低缓存参考命令：

```powershell
ffplay.exe -fflags nobuffer -flags low_delay -framedrop `
  -rtsp_transport tcp -probesize 32 -analyzeduration 0 `
  -sync video -an "rtsp://开发板IP:8554/live/main_stream"
```

正式报告必须记录使用TCP还是UDP、播放器版本和全部低缓存参数。低缓存配置会改变
结果，不能把不同参数的样本混在同一组统计中。

## 自动采集截图

在Windows PowerShell中进入仓库根目录：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
./scripts/capture_optical_latency_windows.ps1 `
  -Samples 120 `
  -IntervalMs 500
```

默认约60秒采集120张全桌面PNG，路径会显示在终端。截图使用同一桌面瞬间，因此
PowerShell定时器的调度误差不会直接进入两块计时器的差值。

## 自动识别与统计

1. 用Chrome/Edge打开 `scripts/optical_latency_analyzer.html`。
2. 一次选择采集目录中的全部PNG。
3. 在第一张截图上紧贴白色外框，框选浏览器里的实时九位计时器。
4. 再紧贴播放器画面里的计时器外框进行框选。若视频已旋转，设置对应的
   `90/180/270`旋转角度，使两个区域均恢复为水平九位数字。
5. 点击“分析全部截图”。页面自动复用两个ROI，解析时间码、处理跨午夜差值，
   拒绝超过“最大合理时延”的异常样本，并输出平均值、P50、P95、P99和最大值。
6. 点击“下载CSV”保存逐样本证据。正式验收至少需要100个有效样本。

识别不依赖OpenCV、Tesseract、Python或联网服务，只需要浏览器。失败样本不会被
静默计为0，而会在表格和CSV中保留具体错误。若大量失败，应重新框选ROI、校正旋转，
或改善屏幕亮度、对焦与拍摄角度。

## 建议判定口径

- 有效样本不少于100个，识别成功率不低于95%。
- 目标区间为120–250 ms；工程验收可先使用 `P50 <= 200 ms`、
  `P95 <= 250 ms`，同时记录P99和最大值，不用平均值掩盖长尾。
- 测试期间双VENC、AI、OSD和音频必须保持开启，`ErrCnt=0`，客户端不得出现
  H.264解码错误、断流或自动重连。
- 至少分别测默认客户端缓存和低缓存配置；需要比较传输协议时，再分别测TCP与UDP，
  每组重新采集独立CSV。

## 误差与限制

- 60 Hz计时器显示和客户端显示各有约一帧量化误差，单样本可能波动约16.7–33.4 ms；
  因此必须看100个以上样本的百分位，不能只拍一张照片。
- 摄像头滚动快门可能拍到数字切换中间态。七段码分析器会尽量拒绝这种样本，不能
  通过放宽规则把无法识别的帧强行算成有效数据。
- 自动识别能处理旋转和轻微缩放，但不能校正严重梯形透视。摄像头应尽量正对屏幕。
- 光学总时延只能说明全链路结果。若不达标，再结合
  `runtime-latency.md`、Wi-Fi RTT和客户端缓存参数定位具体阶段。
