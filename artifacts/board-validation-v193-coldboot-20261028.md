  `/root/rv1126_objects/rv1126-object`。

  `pid=802`、`watchdog=873`、`restarts=0`。
- 冷启动后 `health` 通过：主/子 VENC、AI、OSD、音频、TNR、
  RTSP 和看门狗均正常，`ErrCnt=0`。
- 结论：**v1.9.3 真实物理断电冷启动通过**。
- 独立发现：媒体服务可自启，但 `wpa_supplicant` 没有随开机启动，
  `wang` 不会自动连接。本次通过现有 `/etc/wpa_supplicant.conf`
  手动连接后继续 Wi-Fi 验收。

## 30分钟全功能验收

- 时间：10:22:43至10:52:54，请求持续1800秒。
- RTSP TCP 双流8轮：4轮通过，4轮失败。
  - 第1轮：主流8901帧/29.67 FPS，子流9001帧/30.00 FPS，
    主流 H.264 宏块解码错误。
  - 第2轮：主流8658帧/28.86 FPS，子流8997帧/29.99 FPS，
    `RTP bad cseq` 和 H.264 解码错误。
  - 第3、4、7、8轮：主/子流均约30 FPS，通过。
  - 第5轮：宿主机报 `Network is unreachable`。
  - 第6轮：RTSP 握手10秒内无首帧。
- 健康检查8/8通过，音视频检查1/1通过，看门狗重启0次。
- CPU P50/P95/最大值为13.43%/14.56%/15.89%。
- RSS 从153668 kB降到133116 kB，最大153668 kB；线程固定34，
  FD 156至160。

- 结论：**板端全功能与资源稳定，但严格30分钟整体验收失败**；
  失败集中在旧 `librtsp` TCP 主流路径和一次宿主机路由不可达。

## 10分钟音视频PTS与漂移

- 使用600秒墙钟超时录制，不使用 `ffmpeg -t`，避免媒体PTS跳变
  导致测试提前结束。
- 收到视频17154帧，平均28.59 FPS；预期18000帧，少846帧。
- 收到音频28595包；预期30000包，少1405包。
- 视频10次PTS大间断，音频9次PTS大间断；两路累计缺口都约28秒。
- 采集时出现1次 `RTP bad cseq`、8次RTSP `CSeq expected`；离线解码
  检出10次H.264解码错误和10次损坏帧，并有非单调DTS。
- 10、60、120、300、590秒检查点的视频相对最近音频PTS偏差在
  -9至+5 ms之间，未观察到音视频之间逐渐扩大的漂移。
- 板端同期统计主/子VENC `pts_gap=0`、音频采集与发送相等、
  RTSP队列高水位2/8、看门狗重启0次。
- 结论：**收到的音视频相对同步关系稳定，但RTSP传输连续性不合格**。
  音视频同时跳过约28秒，不能宣称长时音视频验收通过。
